# 정부 요약서형 1페이지 보고서

> **English:** Korean government-style A4 one-page `.docx` (label/content table, nested
> tables, superscript citations). For a Western executive/startup one-pager, use
> `exec-one-pager` instead.

한국 정부지원 사업 요약서 / 추진계획(안) 형식의 A4 1페이지 docx 보고서를 만드는 스킬이다. 라벨-내용 표 한 장, 소표, 위첨자 근거주석까지 고정된 스타일로 재생산한다.

## 언제 쓰는가

- 사용자가 새 주제로 1페이지 요약서를 요청할 때 (예: "이 주제로 1페이지 요약서 만들어줘")
- 사업명, 문제점, 해결방안, 시장규모, 성공/중단 기준 등을 채워 정부지원 사업 요약서를 만들 때
- 스크립트에 내장된 샘플과 동일한 표/스타일 구조를 다른 주제에 재사용할 때

## 빠른 실행 절차

1. 아래 **내용 채우기 지침**과 **문체 규칙**에 따라 사용자 제공 정보를 11개 라벨 행 내용으로 정리한다. 부족한 정보는 사용자에게 묻거나, 공개 자료를 근거로 합리적으로 채우고 근거를 표시한다.
2. `scripts/report_generator.js`를 작업 디렉토리로 복사한다.
3. 파일 상단 `DATA` 객체만 새 내용으로 교체한다 (표 구조·스타일 엔진은 건드리지 않는다).
4. `npm install docx --no-save`(또는 이미 설치되어 있으면 생략) 후 `node report_generator.js`로 실행해 `.docx`를 생성한다.
5. 생성된 파일을 사용자에게 전달한다. 파일 제공 도구가 있는 환경이면 그 도구를 쓴다.

내용을 채울 정보가 대화 중에 이미 충분히 주어졌다면, 되묻지 말고 바로 초안을 만들고 어떤 가정을 했는지 짧게 밝힌다.

## 형식 규칙

- 산출물은 A4 1페이지 docx. 넘치면 문장을 줄이고 표를 압축한다.
- 전체를 좌측 라벨, 우측 내용의 표 한 장으로 구성한다. 정부지원 사업 요약서 양식을 따른다.
- 제목은 한 줄로 쓰고 아래에 이중 밑줄을 넣는다.
- 라벨 열은 옅은 회색 음영에 굵은 글씨, 가운데 정렬.
- 표 안의 소표는 헤더 행을 짙은 바탕에 흰 글씨로, 본문은 흰 배경으로 둔다.
- 폰트는 바탕체(명조)로 통일한다. 제목만 굵게.
- 기본 라벨 행 순서: 사업명, 핵심요약, 현황 및 문제점, 추진배경, 해결방안, 제품·기능, 시장·대상, 사업화 방안, 성공·중단 기준, 추진일정, 참고·근거.
- 제품·기능 행은 신사업·서비스 사업계획서에 필수로 포함한다. 생략하면 "뭘 만드는지 없다"는 피드백이 발생한다.

## 문체 규칙

- 모든 항목은 명사형으로 끝맺는 개조식으로 쓴다.
- 핵심만 담고 수사와 형용을 걷어낸다. 한 항목은 한 사실만 전달한다.
- "A가 아니라 B" 같은 대비 구문을 쓰지 않는다.
- 긴 대시(em dash, —)를 쓰지 않는다. 연결이 필요하면 짧은 하이픈(-)이나 평서문으로 처리한다. 이 규칙은 보고서 본문뿐 아니라 사용자에게 전달하는 채팅 답변에도 동일하게 적용한다.
- 강조용 따옴표 남발을 피한다.
- 수치와 단정적 주장에는 근거를 붙인다. 본문에는 위첨자 번호를 달고, 참고·근거 행에 출처를 적는다.
- 시장 수치는 추정임을 참고·근거 행에 명시한다.

## 내용 채우기 지침

- 핵심요약은 4줄 이내. 문제, 원인, 해법, 대상 순으로 한 줄씩.
- 현황 및 문제점은 사실 4개 이내. 각 줄 앞에 괄호 키워드를 붙여도 되고 생략해도 된다.
- 해결방안은 구분, 내용, 결과 3열 소표로 정리하고 아래에 안전장치나 전제를 한 줄 붙인다.
- 제품·기능은 단계, 내용 2열 소표로 유저 플로우를 단계별로 정리한다. 플랫폼·기술 스택·첫 사용자 확보 경로를 아래에 한 줄로 붙인다. 신사업이면 반드시 포함.
- 시장은 TAM, SAM, SOM 3행 소표로 정리한다.
- 성공·중단 기준은 중단(Kill)과 전진(Go) 2열 소표로 대비시킨다.
- 참고·근거는 출처를 짧게 나열한다.

## 대화 중 프롬프트로 즉석 요청받을 때

사용자가 스크립트 실행 없이 대화 중 빠르게 초안을 원하면, 아래 틀을 채워 넣은 뒤 그 내용으로 바로 `scripts/report_generator.js`의 DATA를 구성한다 (사용자에게 다시 붙여넣기를 요구하지 않는다).

```
[내용]
- 주제:
- 현황 및 문제점:
- 추진배경:
- 해결방안:
- 제품·기능(유저 플로우 단계별, 플랫폼·기술 스택):
- 시장·대상(TAM/SAM/SOM):
- 사업화 방안:
- 성공·중단 기준:
- 추진일정:
- 근거·출처:
```

## 스크립트 사용법 (scripts/report_generator.js)

- 상단 `DATA` 객체만 바꾼 뒤 `node report_generator.js`로 실행한다. 사전에 `npm install docx`가 필요하다.
- 표 구조와 스타일 엔진(하단 "이하 스타일 엔진" 부분)은 고정이므로 수정하지 않는다.
- 근거가 필요한 항목은 문장 객체에 `sup: 1` (또는 2, 3...)을 넣고, 참고·근거 행에 해당 번호의 출처를 적는다.
- 소표가 필요한 칸은 `{ table: { widths, header, body } }` 객체로 넣는다.
- `m`은 글머리 기호(◦, - 등), `label`은 단계 라벨(예: "1단계"), `size`는 폰트 크기(기본 17) 조정용이다.
- 파일 안의 DATA는 구조 확인용 가상 샘플이다. 사업명, 수치, 출처가 모두 실제 데이터가 아니므로 새 주제로 쓸 때는 전체를 교체한다.
- 한글 폰트(바탕)가 없는 환경에서는 렌더링이 달라질 수 있다. 필요하면 `FONT` 상수만 교체한다.

## 체크리스트 (제출 전)

- [ ] 라벨 행 11개가 정해진 순서대로 있는가 (제품·기능 포함)
- [ ] 신사업 보고서에 제품·기능 행이 있는가 (없으면 추가)
- [ ] 샘플 DATA의 문구·수치가 남아 있지 않은가 (전체 교체 확인)
- [ ] 모든 문장이 개조식 명사형으로 끝나는가
- [ ] "A가 아니라 B" 대비 구문이 없는가
- [ ] em dash(—)가 없는가 (짧은 하이픈 - 으로 통일)
- [ ] 수치·단정적 주장에 위첨자 근거 번호가 붙고 참고·근거 행에 대응 출처가 있는가
- [ ] 시장 수치 옆에 "추정" 표시가 참고·근거 행에 있는가
- [ ] A4 1페이지에 들어가는가 (넘치면 문장/표 압축)
